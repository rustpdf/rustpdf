# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A PDF library in Rust built as a **single Rust core + thin foreign-language bindings** (paid product, portable by design). Work follows the phased plan in `project.md`; progress is tracked in `TASKS.md`, and **deferred/partial items in `PENDING.md` (keep it updated as you finish or defer work)**. Currently **Fase 0–6 are complete plus Fase 7.1–7.6**: 7.1 signatures (`pdf::sign`), 7.2 PAdES B-B/B-LT/B-LTA (`pdf::add_dss`/`pdf::timestamp`), 7.3 encryption RC4/AES-128/**AES-256-R6** (`EditableDoc::encrypt_with`), 7.4 **PDF/A-1b/2b/2a/3b/3a** (`Document::pdfa()`/`pdfa_a()`/`pdfa_with(PdfaLevel)`; A-3 attachments via `attach_file`), 7.5 Tagged PDF / PDF/UA-1 with **semantic tags** H1–H6/Figure+Alt/Table + **lists** `/L`-`/LI`-`/LBody`/**Caption**/header `/Scope`+`/Headers`-`/ID` (`Document::tagged()`/`pdfa_a()`, public `StructTag`), 7.6 layout (`pdf::Report`). Also: **AcroForm authoring** (6.7, `Document::text_field`/`checkbox`/`radio_group`/`dropdown` with generated `/AP` + hierarchical names, `form.rs`), **object dedupe + generic incremental update** (`EditableDoc::optimize`/`to_bytes_incremental`), and **CSPRNG-hardened encryption** (`getrandom`). Reads+writes **AES-256/R6** (`crypt.rs`/`encrypt.rs`) and **object streams + xref streams** (`writer::set_object_streams`). Deferred: 7.7 HTML→PDF (out of scope), network TSA/OCSP, inline `/Span`, read→PDF/A conversion (see `PENDING.md`). The `layout` crate stays a skeleton — flow layout lives in `pdf::flow`.

**Validators:** `qpdf`/`mutool`/`pdftotext`/`pdfsig`/`openssl`/`verapdf` are all installed. `testkit::validate()` runs only the **structural** validators (qpdf, mutool) — `verapdf` is NOT in it (it checks PDF/A conformance, which a plain PDF fails); use `validate_with(path, &[Validator::VeraPdf])` for PDF/A files. The test sandbox spawns these unreliably, so external-tool tests skip when a tool can't run.

### Tagged PDF / accessibility (Fase 7.5)

`Document::tagged()` (and `pdfa_a()` = `pdfa().tagged()`) builds a **nested** structure tree at `to_bytes` via `tagtree::TreeBuilder`. Each tagged leaf (text block or figure) carries a `StructTag` leaf role (`P`/`H1`–`H6`/`Figure`/`TD`/`TH`/…, defaults to `P`) plus an `ancestors: Vec<(StructTag,u64)>` grouping path; the builder lazily creates shared group elements **keyed by the full `(StructTag,u64)` path prefix** (NOT just the u64 — a list `L#0` and a table `Table#0` both start their counters at 0, so keying on the number alone merged them; real bug veraPDF caught) so e.g. a table cell nests `Table → TR → TD` and a list item nests `L → LI → LBody`. Text is wrapped in `/<Tag> <</MCID n>> BDC … EMC` (via `text::emit`, using `obj.tag.name()`); figures (`Page::figure`) in `/Figure <</MCID n>> BDC … Do … EMC` with `/Alt` (UTF-16BE via `cos::PdfString::text`); decorative graphics/images (`Page::draw_image`) in **`/Artifact BMC … EMC`** (must be `BMC`, not `BDC` — `BDC` needs a properties operand; real bug veraPDF caught). Header cells (`TH`) get `/A <</O /Table /Scope /Column>>` **and** a stable `/ID`; body cells (`TD`) get `/Headers [id]` for their column (the cell's column index is threaded via `TextObject::col`/`Paragraph::with_col`) — both association mechanisms, UA 7.5. `Report` sets these automatically: `heading_level` → H-tags, `list()` → `L`/`LI`/`LBody`, table cells → `Table`/`TR`/`TH`/`TD`; `Caption` via `tag()`. **Inline `/Span`** (`TextObject::show_span`): a tagged run is wrapped in *nested* marked content `… /Span <</MCID m>> BDC … EMC …` inside the block's BDC; `text::emit` allocates MCIDs from a `&mut i32` counter and returns the spans, and the block leaf's `/K` becomes a mixed array `[block_mcid, span_refs…]` (the `Span` element is a child of the `P`, registered in the ParentTree by its own MCID). A `ParentTree` (key = page `/StructParents`) maps each page's MCIDs to its leaf elements. Catalog gets `/MarkInfo<</Marked true>>`, `/StructTreeRoot`, `/Lang (en-US)`, `/ViewerPreferences<</DisplayDocTitle true>>`; XMP adds `pdfaid:conformance=A` + the `pdfuaid` identifier **with its `pdfaExtension` schema**. veraPDF validates both **PDF/A-2a** (`-f 2a`) and **PDF/UA-1** (`-f ua1`) for the basic, rich (heading+figure+table) and finer (list+caption+headers) docs.

### PDF/A (Fase 7.4) — levels A-1b/2b/2a/3b/3a

`Document::pdfa()` (=A-2b), `pdfa_a()` (=A-2a), and `pdfa_with(PdfaLevel)` make `to_bytes` add (in `pdfa.rs`): an embedded sRGB ICC profile stream (`/N 3`, the CC0 `assets/icc/sRGB.icc` via `include_bytes!`), an `/OutputIntents` entry (`/S /GTS_PDFA1`, `DestOutputProfile` → ICC), an uncompressed XMP `/Metadata` stream with the `pdfaid` identifier (`part` = 1/2/3 from `PdfaLevel::part()`), and a trailer `/ID`. **The XMP MUST stay in sync with `/Info`** (PDF/A 6.7.3): both from one `info_entries()` list. **A-1b** forces the header to PDF 1.4, requires a `/CIDSet` in each CIDFont descriptor (built in `font.rs`, bit-length = the embedded subset program's `numGlyphs`, read back via `Font::from_bytes` — must cover *all* glyphs in the program, not just referenced ones, per veraPDF 6.2.11.4.2), and must not use object streams. **A-3** allows arbitrary attachments: `Document::attach_file(name, mime, data, AFRelationship, desc)` → `attach.rs` emits an `/EmbeddedFile` (typed, MIME `/Subtype`, `/Params` with size+ModDate) wrapped in a `/Filespec` (`/AFRelationship`, `/F`, `/UF`) registered in catalog `/Names /EmbeddedFiles` **and** `/AF`. veraPDF confirms **1b, 2b, 2a, 3b and 3a** all `isCompliant=true`.

## Toolchain quirk — cargo is NOT on PATH

`cargo`/`rustc`/`rustup` are not on `PATH`. Prepend the toolchain before any cargo command (or use the `Makefile`, which honors `CARGO=...`):

```sh
export RUSTUP_HOME="$HOME/.rustup"
export PATH="$HOME/.rustup/toolchains/stable-aarch64-apple-darwin/bin:$HOME/Library/Caches/puccinialin/cargo/bin:$PATH"
```

External validators present: `qpdf`, `mutool`. **`verapdf` is not installed** — `testkit` reports it `Unavailable` and skips it rather than failing.

## Architecture — two layers, never blur them

This separation is the core design decision (ADR `docs/adr/0001-porting-strategy.md`) and the most common way to get the design wrong:

1. **Idiomatic Rust core** (`cos`, `writer`, `graphics`, `pdf`, + future `parser`/`fonts`/`images`/`layout`) — rich and **unrestricted**: `Result`, builders, enums-with-data, generics. This is what Rust users consume. Do **not** "FFI-ify" it.
2. **`ffi` crate (`pdf-ffi`)** — the **only** layer crossing the C boundary, and the only one bound by the rules in `docs/FFI_RULES.md`: opaque handles (`*mut PdfDocument`, `*mut PdfEditable`), `extern "C"`, no `Result`/generics/panic across the line, `PdfStatus` return codes + thread-local last-error, every export wrapped in `catch_unwind`, every handle/buffer has a `*_free`. The C header `include/pdf.h` is generated by `cbindgen` in `crates/ffi/build.rs`. The surface is now **full** (~60 exports), split across `lib.rs` (core + helpers `cstr`/`bytes`/`emit_buffer`/`transform_doc`/`with_doc`), `build.rs` (document authoring: fonts/text/images/PDF-A/tagging/attachments/forms — enum args passed as small ints), `editable.rs` (`PdfEditable` manipulation + `pdf_extract_text`), and `signing.rs` (`pdf_sign`/`pdf_timestamp`/`pdf_add_dss`). Consuming builders (`pdfa`/`tagged`/…) are applied via `transform_doc` (swap the `Document` out, transform, put back); registration ids cross as `c_int` via `FontId/ImageId::index()`/`from_index()`.

The fluent API does **not** cross the C ABI — each binding rebuilds its own idiomatic wrapper over the raw FFI (`bindings/python/rustpdf/__init__.py`: context-manager `Document`/`EditableDoc` over `ctypes`, plus `extract_text`/`sign`/`timestamp`/`add_dss` and `PdfaLevel`/`Align`/`AFRelationship`/`Encryption` enums; packaged via `bindings/python/pyproject.toml`). `make python-test` keeps the **byte-identity dogfood** (same vector drawing → identical bytes Rust vs Python) and exercises the whole surface; signing is dogfooded with the committed `crates/pdf/tests/fixtures` key/cert. A second binding, **C#/.NET** (`bindings/csharp/RustPdf`), uses source-generated P/Invoke (`LibraryImport`, UTF-8 string marshalling, a `NativeLibrary.SetDllImportResolver` that finds `target/{debug,release}` or `RUSTPDF_LIB`) with the same `Document`/`EditableDoc`/`Pdf` shape; `bindings/csharp/Sample` runs the full-surface smoke test (`dotnet run --project bindings/csharp/Sample`). A third binding, **Go** (`bindings/go/rustpdf`), uses cgo (`#cgo CFLAGS`/`LDFLAGS` pointing at `include/` and `target/{debug,release}`; the macOS dylib's absolute install name resolves at runtime, Linux gets an `-rpath`) with `Document`/`EditableDoc` + package funcs; `go test ./bindings/go/...` exercises the full surface. A fourth binding, **PHP** (`bindings/php`, `ext-ffi`), loads the cdylib via `FFI::cdef` (the C declarations are a trimmed copy of `pdf.h` with `PdfStatus`→`int`, embedded in `Ffi.php`; `const char*` returns auto-convert to PHP strings; `cast`/`new` are called on the `$ffi` instance, not statically) with `RustPdf\{Pdf,Document,EditableDoc}` + enums; `php bindings/php/test/run.php` exercises the full surface. A fifth binding, **Ruby** (`bindings/ruby`, Fiddle stdlib), builds memoized `Fiddle::Function`s from a signature table (`PdfStatus`→int; `const char*` returns via `Pointer#to_s`; out-buffers via `Pointer.malloc`+`#ptr`; text returns `force_encoding("UTF-8")`) with `RustPdf::{Document,EditableDoc}` + module funcs; `ruby bindings/ruby/test/run.rb`. A sixth binding, **Node.js/TypeScript** (`bindings/node`, Koffi pure-FFI — no node-gyp), declares the C functions with prototype strings, uses `_Out_` params (1-element arrays) + `koffi.decode(ptr,'uint8_t',len)`→Uint8Array for out-buffers, passes Node Buffers for `uint8_t*`, JS string[]→`char**`, Float64Array→`double*`; `RustPdf.{Document,EditableDoc}` + funcs + `index.d.ts` types; `node bindings/node/test/run.js`. A seventh binding, **Java** (`bindings/java`, JNA pure-FFI — no native build), maps the C ABI in `FFI.java` (`com.sun.jna.Library` interface, `OPTION_STRING_ENCODING=UTF-8`, `uintptr_t`→Java `long`, a locator that finds `RUSTPDF_LIB` or `target/{debug,release}`), with `dev.rustpdf.{Pdf,Document,EditableDoc}` (AutoCloseable) + enums; `make java-test` (`mvn test-compile exec:java`) runs the full-surface `SmokeTest`. An eighth binding, **Delphi / Free Pascal** (`bindings/delphi/RustPdf.pas`, pure FFI — no native build), **dynamically loads** the cdylib (a load/sym shim over FPC `dynlibs` / Win32 `LoadLibrary` / POSIX `dlopen`, with a `RUSTPDF_LIB`-or-`target/{debug,release}` resolver) and binds all ~60 exports as `cdecl` function pointers, exposing `TPdfDocument`/`TPdfEditable` (chained mutators return `Self`, freed via `destructor`) + a `Pdf` record (static `Version`/`ActivateLicense`/`ExtractText`/`Sign`/`Timestamp`/`AddDss`) + enums (`TPdfaLevel`/`TPdfAlign`/`TAFRelationship`/`TEncryption`); strings cross as UTF-8 (`UTF8String`), buffers as `TBytes`, errors raise `ERustPdf` with the `Status`; compiles under both Delphi (10.x+) and FPC 3.2+ via `{$IFDEF FPC}{$MODE DELPHI}{$ENDIF}` + `{$CODEPAGE UTF8}`; `make delphi-test` compiles+runs `bindings/delphi/test/run.dpr` (skips when neither `fpc` nor `dcc64` is on PATH). The lib resolver also checks the **executable's own directory** + CWD (not just `target/{debug,release}`), so deployment = drop the cdylib beside the app; `make delphi-dist` (`scripts/package.sh`) builds the cdylib for every installed Rust target and assembles a versioned zip (unit + per-platform `lib/<os-arch>/` + sample + `boss.json`) — Delphi has no central registry, so customers get an archive or the Git/Boss repo. A ninth binding, **Swift** (`bindings/swift`, SwiftPM), **links** the native lib (it does NOT `dlopen` — that was an earlier iteration, dropped because iOS can't `dlopen` an arbitrary path): a `CRustPdf` clang target vendors a copy of `include/pdf.h` (with the function return type `PdfStatus`→`int` so it bridges to Swift `Int32`, like the PHP/Delphi header copies), and `Native.swift` holds one typed reference per linked C export (plain function-type aliases — NOT `@convention(c)`, since these are forwarding values not C callbacks; an `@convention(c)` alias + a direct C-function reference don't unify). The in-repo `Package.swift` links the dev tree (`-L<repo>/target/{debug,release} -lpdf_ffi -liconv` via `unsafeFlags`, repo root found by walking up from `#filePath`); the **distributed** package links a **static** `libpdf_ffi.a` carried in an `.xcframework` (so it works inside an iOS app bundle, no sidecar lib). Exposes reference-type `Document`/`EditableDoc` (`OpaquePointer?` handle freed in `deinit`; chained mutators return `self`) + a `Pdf` enum (static `version`/`activateLicense`/`extractText`/`sign`/`timestamp`/`addDss`) + Swift enums (`PdfaLevel`/`Align`/`AFRelationship`/`Encryption`/`PdfVersion`); strings cross via `withCString`/`strdup`, binary payloads as `[UInt8]` (out-buffers copied then `pdf_buffer_free`d by `takeBytes`; parallel `(ptr,len)` arrays for `addDss` built by flattening into one contiguous buffer so all element pointers stay valid at once), errors `throw PdfError { status, message }`; `uintptr_t`→`UInt`. `make swift-test` runs the full-surface `SmokeTest` via `swift test` (skips when no `swift` on PATH); `swift run rustpdf-example` is a runnable demo. `make swift-dist` (`bindings/swift/scripts/package.sh`) builds the staticlib for every buildable Apple target (macOS arm64+x86_64 lipo'd, iOS device arm64, iOS simulator arm64+x86_64 lipo'd — best effort, like `delphi-dist`), assembles `RustPdfFFI.xcframework` via `xcodebuild -create-xcframework`, and stages a consumable package under `bindings/swift/dist/` (stable dir name `RustPdf` so a path-dep keeps identity `RustPdf`) with a `.binaryTarget` `Package.swift` (consumer links `iconv`, the staticlib's only non-system dep — `otool -L`); also emits a standalone `RustPdfFFI-<v>.xcframework.zip` + `swift package compute-checksum` for URL-hosted `.binaryTarget(url:checksum:)`. `dist/` is gitignored (large libs). Smoke tests: `make {python,csharp,go,php,ruby,node,java,delphi,swift}-test`. All nine bindings get env-based license auto-activation for free (it lives in the core).

### Crate dependency flow

`cos` (zero deps) → `writer`/`graphics` (depend on `cos`) → `pdf` (orchestrates all three) → `ffi` (wraps `pdf`). `testkit` is independent (validators + visual diff) and is a **dev-dependency** of `pdf`. `license` (Ed25519 feature licensing, zero internal deps) is a dependency of `pdf`.

### Feature licensing (`license` crate)

Corporate features are gated behind an offline, Ed25519-signed license; basic generation stays free. `license::verify(token)` checks signature (against an embedded public key, overridable at build via `option_env!("RUSTPDF_LICENSE_PUBKEY")`) + expiry, returning a `License { licensee, issued, expires, features: u32 }`. `pdf` holds a process-global `static ACTIVE_LICENSE: RwLock<Option<License>>`; `pdf::activate_license(token)` verifies+stores it (token is trimmed), and `pdf::require(Feature)` (called inside the gated paths) errors unless the active license grants the feature and isn't expired. **Auto-activation:** `require`/`active_license` call `ensure_env_license()`, which — while nothing is active — picks a token up from `RUSTPDF_LICENSE` (inline) or `RUSTPDF_LICENSE_FILE` (path); so a customer can just set an env var with the emailed token, no code, works across Rust/FFI/Python. Customers never rebuild — only the vendor embeds the pubkey at build. **Gated:** `Document::to_bytes` when `pdfa`(→`Feature::Pdfa`) / `tagged`(→`Accessibility`); `EditableDoc::to_bytes` when encrypting(→`Encryption`); `pdf::sign`/`timestamp`/`add_dss`(→`Signatures`). Failures surface as `BuildError::License`/`SignError::License` (`PdfStatus::License` over FFI, `PdfError` in Python). The token wire format is `hex(payload).hex(sig)` (payload = LE record). Tokens are minted by `crates/license/examples/licctl.rs` (keygen/issue) with the **private seed** (never embedded). Tests/examples use the committed **dev** keypair: pubkey embedded in `license/src/lib.rs` (`DEV_PUBLIC_KEY_HEX`), seed + an all-features ~100-year token in `crates/license/fixtures/` (`dev_seed.hex`, `dev_license.txt`). Gated Rust tests call a local `lic()` helper that activates `dev_license.txt`; `crates/pdf/tests/licensing.rs` proves blocked-without/forged/expired/partial. Production ships a binary built with `RUSTPDF_LICENSE_PUBKEY=<vendor pubkey>`, which invalidates the dev tokens. See `docs/LICENSING.md`.

### Two invariants enforced by code

- **`Send`, not `Sync`** (ADR `0002`): the object graph is an arena — `writer::Document` holds `objects: Vec<Option<Object>>` indexed by object number, **never `Rc`/`RefCell`**. A compile-time `assert_send` in `crates/pdf/src/lib.rs` tests breaks the build if this regresses.
- **Deterministic output**: no timestamps, no hash-map ordering (`cos::Dict` keeps insertion order). This is what makes the Python-vs-Rust byte-identity dogfood (Fase 1.7) possible — keep it that way.

### How a PDF is built (request flow)

`pdf::Document` (page list + content) → `to_bytes()` reserves catalog/pages refs up front (so pages can point back via `/Parent` before the root exists), fills page dicts + content streams, then `writer::Document::write()` emits header + binary marker, indirect objects (recording byte offsets), the classic xref table, and the trailer. `graphics::Content` is a fluent byte-buffer builder of content-stream operators; numbers are written in fixed (non-exponential) notation for determinism.

### Text & fonts (Fase 3) — two-pass, deferred encoding

Text is the subtle part. A page holds an ordered `Vec<PageItem>` (`Graphics` | `Text` | `Paragraph`) so z-order is preserved; `page.content()` extends the current graphics segment, `page.text()`/`page.paragraph()` start new items. Glyph ids written into a content stream are **subset** ids, which aren't known until subsetting — so text is stored *symbolically* (runs of chars + style) and resolved at `to_bytes()` time in two passes:

1. **collect_usage** (`text.rs`) shapes every run (`fonts::shape`, rustybuzz) to gather used original glyph ids per font and a glyph→Unicode map (from shaping clusters) for `ToUnicode`.
2. **build_font** (`font.rs`) subsets each used font (`fonts::Subset` via the `subsetter` crate) and emits one universal representation: **Type0 + CIDFontType2 + `Identity-H` + identity `CIDToGIDMap`**, so the CID written in the stream *is* the subset glyph id. Metrics are scaled to glyph space (1000/upem).
3. **emit** re-shapes each run, maps old→new gids, and writes a `TJ` array whose numeric adjustments carry kerning (`raw_advance − shaped_advance`, scaled).

There is no separate simple/WinAnsi font path — the Type0 path is universal and is what makes Unicode, subsetting and CJK work together. `paragraph.rs` is the L2 layer: greedy line breaking using shaped widths, alignment, and justification (extra space distributed as `TJ` adjustments between word-runs). All font metrics flow from `fonts::Font` (owns its bytes, re-parses a `ttf_parser::Face` on demand to stay `Send`).

### Digital signatures (Fase 7.1)

`pdf::sign` (`sign.rs`) appends an **incremental update** (it does NOT rewrite): new objects (sig dict, signature widget, `AcroForm`) + re-emitted catalog (with `/AcroForm`) and first page (with `/Annots`), then a classic `xref` section chained via `/Prev`. The signature dict is built by hand (not cos) to control placeholder widths: `/ByteRange [` + a fixed 48-byte space-padded field + `]`, then `/Contents <` + `RESERVED*2` hex zeros + `>`. Two-pass: assemble with placeholders → locate `<` of `/Contents` → compute `ByteRange = [0, a, a+gap, rest]` (gap = `RESERVED*2 + 2`, excluding the `<...>`) → overwrite the fixed-width ByteRange field → SHA-256 the two segments → build PKCS#7/CMS detached (`cms` `SignedDataBuilder` + `SignerInfoBuilder` with `external_message_digest`, RSA `SigningKey<Sha256>`) → hex into the `/Contents` placeholder. **xref entries must be exactly 20 bytes** (`{:010} 00000 n\r\n` — no extra space, that was a real bug). Also supports **visible signatures** (an appearance Form XObject drawn with the standard Helvetica font — no embedding; the standard-14 fonts need only a `Type1`/`Helvetica` font dict), **multiple signatures** (re-sign appends another incremental update, extends the existing AcroForm `/Fields` with a unique `Signature{N}` field name; earlier signatures stay valid as their ByteRange predates the new bytes), and a **certificate chain** in the CMS (chain certs must be distinct — the CMS `SET OF` panics on duplicates). When multiple signatures exist, use `rfind_sub` to target the newest `/Contents` and `/ByteRange`. **PAdES-B-B** (`SignOptions.pades`): switches the subfilter to `ETSI.CAdES.detached` and adds the ESS `signing-certificate-v2` signed attribute (built as raw DER via a tiny `tlv()` helper — ESSCertIDv2 with just `certHash`, sha256 hashAlgorithm omitted as DEFAULT). The cms builder auto-adds `contentType`/`messageDigest`, so the custom attr coexists. **PAdES LTV is implemented offline:** `add_dss` appends a `/DSS` (Document Security Store) with `/Certs`/`/CRLs` streams (B-LT); `timestamp` appends a `/DocTimeStamp` (`ETSI.RFC3161`) whose `/Contents` is a real RFC 3161 TimeStampToken — a CMS SignedData *encapsulating* TSTInfo (messageImprint = SHA-256 of the ByteRange), signed by a `Signer` acting as a self-issued TSA. Both `add_dss` and `timestamp` reuse the same incremental-update machinery; `append_signature` is the shared core (sign and timestamp differ only in `/Type`+`/SubFilter` and the `make_contents` closure). RFC 3161 TSTInfo and the signing-certificate-v2 attribute are hand-built as DER via `tlv()`. Validate the timestamp token with `openssl cms -verify ... -noverify` ("CMS Verification successful"). What still needs network/external infra: a *trusted* TSA, OCSP/CRL fetching (caller supplies DER today), `/VRI`, and a reference PAdES validator. Validate with `pdfsig` in the shell ("Signature is Valid"); the sandbox can't spawn it, so tests check structure + ByteRange math + that `/Contents` DER-decodes as CMS SignedData + that our own parser reads the signed incremental file.

### Layout engine & encryption (Fase 7)

`pdf::Report`/`Table` (`flow.rs`) stack blocks down the page measuring each with the paragraph engine, breaking to a new page (and repeating table headers) when content overflows; running header + page-number footer are stamped on every created page. `flow.rs` reaches into `Document`'s private `pages`/`fonts` (it's a sibling module) — measure with `&doc.fonts` first, then mutate `doc.pages[i]` (sequential, no borrow overlap). `EditableDoc::encrypt`/`encrypt_with` (`encrypt.rs`) sets up standard-handler encryption applied at `to_bytes`: derive file key + `/O`/`/U` (RC4-based, R3 algorithms) → encrypt every object's strings/streams with a per-object key (RC4 or AES-128-CBC) → add the `/Encrypt` dict *after* (never encrypted) → writer emits `/Encrypt` + `/ID` in the trailer. **AES-256/R6** (`encrypt_with(Encryption::Aes256, …)`) computes `/U`/`/UE`/`/O`/`/OE`/`/Perms` (Algorithms 8–10, `hash_2b`) and encrypts with the file key directly (no per-object key); the parser's `crypt.rs` reads it via Algorithm 2.A/2.B. The AES IVs and (for R6) the file key/salts come from the OS **CSPRNG** (`getrandom`, `random_bytes()` in `encrypt.rs`) so each encryption is unique — validated by `qpdf` for user **and** owner passwords; encrypted output is no longer byte-reproducible, but the determinism invariant only applies to plain docs (which never reach `encrypt.rs`). **Object streams**: `EditableDoc::compact(true)`/`optimize()` → `writer::set_object_streams` packs every non-stream object into one `/ObjStm` + emits a `/XRef` stream (auto-disabled when encrypting). **optimize()** also **dedupes byte-identical objects** (remap refs to one canonical, pages/catalog excluded). **Generic incremental update**: `EditableDoc::to_bytes_incremental(orig)`/`save_incremental` appends only changed/new objects + a classic xref chained via `/Prev`, preserving the original bytes verbatim (signature-safe). **AcroForm authoring** (6.7, `form.rs`): `Document::text_field`/`checkbox`/`radio_group`/`dropdown` build a full `/AcroForm` with generated `/AP` appearance streams (Helvetica/ZapfDingbats in `/DR`, no `NeedAppearances`) and hierarchical dotted names (`a.b.c` → nested parent fields); widget refs are reserved before the page loop so pages can list them in `/Annots`.

### Manipulation & extraction (Fase 6)

`pdf::EditableDoc` (`edit.rs`) is the editing model: `load` parses with `parser`, copies every object into a `BTreeMap<u32, Object>`, and **flattens the page tree** into a `Vec<u32>` page order — so merge/split/reorder/delete/rotate are list ops; the real `/Pages` tree is rebuilt in `finalize()` on `to_bytes`. Merge renumbers the other doc's objects by an offset and deep-remaps references (`remap`); `extract_pages` does reachability (skipping `/Parent`) then compact renumbering; `optimize` drops unreferenced objects and Flate-compresses uncompressed streams. `extract.rs` (`pdf::extract_text`) walks content-stream operators with `parser::Lexer`, maps shown codes to Unicode via each font's `ToUnicode` CMap (2-byte for Type0), and infers spaces (large negative `TJ`) and line breaks (`Tm`/`T*` y-changes). Manipulation tests (`crates/pdf/tests/manip.rs`) re-parse outputs with our own parser (sandbox can't run qpdf); confirm qpdf acceptance manually.

### Parser (Fase 5)

`parser` reads existing PDFs through layered modules: `lexer` (a non-panicking byte tokenizer — it must never panic so the recovery scan can walk arbitrary bytes), `object` (tokens → `cos::Object`, with `N G R` reference lookahead and stream-body capture), `filters` (Flate w/ PNG/TIFF predictors, LZW, ASCIIHex, ASCII85, RunLength; image filters like DCT are terminal and left encoded), `xref` (classic tables, cross-reference streams, hybrid `/XRefStm`, `/Prev` chains, and a brute-force `N G obj` recovery scan), `crypt` (standard security handler: RC4 R2/R3 + AESv2 R4 with per-object MD5 key derivation, **plus AESv3 V5/R6** with the single file key from Algorithm 2.A/2.B — SHA-256/384/512 + AES-128), and `reader` (`PdfReader`). `PdfReader::parse` **materializes every object up front** into a `BTreeMap<u32, Object>` (resolving object streams, applying decryption), so the reader owns no borrowed state and stays `Send` — no `RefCell` caches. `resolve()` returns `&'static NULL` for dangling refs.

**Parser tests use committed fixtures, not live qpdf.** The test sandbox cannot see or spawn `/opt/homebrew/bin/qpdf` (filesystem isolation), so any in-test `which("qpdf")`/`Command::new("qpdf")` silently fails and assertions skip. Real fixtures live in `crates/parser/tests/fixtures/` (generated once with qpdf: `base.pdf`, `modern.pdf` = xref+object streams, `enc_rc4_40/128`, `enc_aes128`, `enc_aes256`). Tests parse fixtures and validate round-trips by **re-parsing with our own parser** (self-consistent), not by shelling out. To confirm qpdf actually accepts round-tripped output, run `qpdf --check` manually in the shell (it works there) — don't add it to the test suite expecting it to run.

### Images (Fase 4)

`images` crate: **JPEG** is embedded *verbatim* (`DCTDecode`) — only the SOF marker is parsed for geometry, never decoded/re-encoded (no generation loss). **PNG** is decoded with the `png` crate (with `Transformations::IDENTITY` so palette indices stay packed and 16-bit samples stay big-endian — exactly PDF's layout) and re-encoded `FlateDecode`; alpha (RGBA/grayscale-alpha/palette `tRNS`) is split into a separate grayscale `/SMask`, and palette images become an `Indexed` color space. `pdf/src/image.rs` builds the Image XObject (+ SMask); `page.draw_image(id, x, y, w, h)` records the image id (so it lands in the page's `Resources /XObject`) and emits `q w 0 0 h x y cm /Im{id} Do Q` into the current graphics segment.

## Serialization conventions

- `cos` objects serialize via `write_to(&mut Vec<u8>)` appending to a caller-owned buffer (one growing buffer per document, no per-object allocation). When adding a COS type, implement both construction/equality and `write_to`, with a round-trip test.
- A `Stream` auto-inserts a direct `/Length` if absent, but preserves an indirect `/Length` reference if the caller set one.
- Escaping lives in `cos::name` (`#XX`) and `cos::string` (literal `\(`/octal, or hex). Edge cases (nested parens, non-ASCII) have dedicated tests — extend them when touching escaping.

## Definition of Done (`project.md` §10)

Every task: edge-case unit tests; passes applicable external validators; visual regression if it renders; corpus round-trip if it touches parser/writer; core stays `Send`; core types don't leak past `ffi`; new dependency's license recorded in `LICENSES.md` and allowed by `deny.toml` (permissive only — this is a paid product). The PR template (`.github/pull_request_template.md`) encodes this checklist.

## Testing infrastructure

`testkit::validate(path)` runs every available external validator and returns one `Pass`/`Fail`/`Unavailable` report each. Integration tests (e.g. `crates/pdf/tests/milestones.rs`) assert that every *available* validator passes and skip missing ones, so the suite is green on a bare machine but rigorous where tools exist. Visual regression: `render_to_png` (mutool) + `visual_diff` (perceptual mean-abs-diff, `0.0..=1.0`).
