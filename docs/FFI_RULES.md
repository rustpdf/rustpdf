# FFI boundary rules (`project.md` §1.4)

These rules apply **only** to the `crates/ffi` crate — the single layer that
crosses the language frontier. The rest of the core stays idiomatic and
unrestricted. Every PR touching `ffi` must satisfy this checklist.

## Hard rules

- [ ] **Opaque handles only** (`*mut PdfDocument`). Never expose a Rust struct
      layout across the boundary.
- [ ] **Nothing forbidden crosses the line:** no generics, lifetimes, traits,
      enums-with-data, `Result`, or **panic** (panic across FFI is UB).
- [ ] **Errors are return codes:** `#[repr(C)] PdfStatus` + a thread-local
      *last-error* string retrievable via `pdf_last_error_message()`.
- [ ] **Every export is panic-safe:** wrap the body in `catch_unwind`
      (or build the cdylib with `panic = "abort"`). A panic must never escape.
- [ ] **Memory ownership is explicit:** whoever creates, frees. Every handle and
      buffer has a `*_free`. Strings are UTF-8 with an explicit `len`.
- [ ] **PDF output** is `(ptr, len)` + `pdf_buffer_free`, or a write callback
      (preferred for streaming/large files).
- [ ] **Crate-type** is `["cdylib", "staticlib"]` (+ `rlib` for in-tree tests).
      The C header is generated by `cbindgen` in `build.rs`.
- [ ] **The C ABI is versioned** and kept **small and stable** (less surface =
      less per-language binding work).
- [ ] **Thread-safety is documented per handle** (Send/Sync? — see ADR 0002).
- [ ] **The C ABI is not chatty:** pass runs/structs/arrays in one call, never
      primitive-by-primitive.

## Anti-pattern to avoid

Do **not** "FFI-ify" the whole core. That ruins the Rust API for no reason. The
discipline lives only at the edge.

## Review aids

* `make header` regenerates `include/pdf.h`; diff it in review to see the
  exported surface change.
* The Rust unit tests in `crates/ffi/src/lib.rs` assert that null handles return
  `PdfStatus::NullPointer` (not a panic) and that a full create→draw→write→free
  cycle leaks nothing.
* The Python reference binding (`bindings/python`) must keep producing output
  byte-identical to the Rust API (dogfood, Fase 1.7).
